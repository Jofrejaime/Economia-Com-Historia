8. Problemas de Arquitetura, Tipagem e Duplicação
Segurança
Rotas /admin/dashboard/** sem canActivate: [authGuard] nem verificação de role === 'admin'
Backend sem middleware de role — qualquer utilizador autenticado pode chamar reviewRequest, POST /documents, notifications/send, etc.
Tipagem
AuthService.me() retorna any; perfil.ts usa userData: any, profileData: any
Interfaces duplicadas por componente (Document, Category, Quiz, User com shapes diferentes)
IDs numéricos no frontend vs UUIDs no backend
Estado e duplicação
AuthService.me() e ProfileService.getMe() fazem a mesma chamada
Lógica de headers auth repetida; sem interceptor
Filtros/pesquisa implementados client-side sobre arrays mock (não escalam)
Rotas inconsistentes
forum/community/discussao sem :id — detalhe sempre o mesmo mock
category-detail.viewDiscussion(id) navega para rota sem parâmetro
README referencia /api/v1; código usa /api (sem versionamento)
Desalinhamento domínio
Admin categorias mock mistura conceitos de community_categories e document_categories (tabelas separadas no backend)
Roles admin UI: admin|curator|researcher|student vs backend: estudante|investigador|professor|admin
Access types frontend: jindungo|restricted|public vs backend: tabela access_levels
Backend incompleto (501)
Contagem: ~35 endpoints declarados mas retornam "Endpoint ready." com HTTP 501 — integração frontend dependerá de implementá-los primeiro ou falhará silenciosamente.
